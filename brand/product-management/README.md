# SORAN｜产品研发与供应链管理

> 目标：以品牌商视角管理产品机会、产品矩阵、单品开发、供应商协作、采购交付和上市复盘。**这是文档与模板系统，不是 ERP 或可运行的 Web 管理系统。**

## 使用顺序

1. [01｜产品规划](./01｜产品规划/README.md)：先在「SORAN 产品矩阵总表.csv」登记一个计划款式，明确消费者价值、价格带和优先级。
2. [02｜单品开发](./02｜单品开发/README.md)：经立项后，按品类建立「商品编码｜产品名称」文件夹，复制 00 内的相关模板，记录询价、评样和规格冻结。
3. [03｜供应商管理](./03｜供应商管理/README.md)：以供应商主体为中心管理资质与长期表现，**单款产品的竞价仍留在对应单品档案**。
4. [04｜采购与质量管理](./04｜采购与质量管理/README.md)：产品定型后依据签认规格、确认样和订单管理交付。
5. [05｜产品复盘](./05｜产品复盘/README.md)：上市后用真实评价、退货、复购与利润决定迭代。
6. [00｜管理规范与模板](./00｜管理规范与模板/产品开发SOP.md)：查阅阶段门、编号规则和可复制模板。

## 关键原则

- 品牌决定消费者价值、核心配置、品质底线、目标价格及批准标准；供应商提出可制造性方案。
- 先做产品路线规划，再进行单品立项；**不将工厂级详细参数当作品牌初期规划必填项**。
- 每个款式使用一个商品编码；不按供应商或颜色尺码重复创建单品档案。
- 正式规格是单品档案中的「产品规格确认书」，调整需记录版本、重新确认受影响的样品/订单。
- 标准档无后缀；如需升级档，可使用 Pro / Max / Ultra；是否配置升级档由具体产品决策确定。
- 品牌已冻结事项以仓库 [brand/decisions.md](../decisions.md) 为准。**模板中的空白不代表已做决策**。

## 数据安全（重要）

**本 GitHub 仓库当前为公开仓库。** 本目录只存放 SOP、空白 CSV 和 Markdown 模板。不要在此提交实际供应商联系人、电话号码、真实采购价格、未公开销售数据、合同、付款信息、客户信息或其他保密业务资料。实际运营数据应保存在具有访问控制的私有空间。当前的 .gitignore 只能降低误提交概率，不能替代权限控制，已跟踪的文件或强制提交仍可能公开。

CSV 使用 UTF-8 编码，可用 Excel、Numbers、WPS 导入。模板文件可复制至内部私有工作空间后填写；本仓库保留公开空白母版。

## 资料归属与交叉引用

| 对象 | 唯一归属位置 | 其他目录如何关联 |
|---|---|---|
| 产品规划与优先级 | 01｜产品规划 | 商品编码 |
| 单款立项、询价、评样、最终规格 | 02｜单品开发/品类/款式目录 | 商品编码、供应商编号 |
| 供应商资质/准入/综合评估 | 03｜供应商管理 | 供应商编号 |
| 采购订单、合同、来货检验 | 04｜采购与质量管理 | 采购订单号、商品编码 |
| 上市经营与消费者反馈 | 05｜产品复盘 | 商品编码 |

特殊合规要求和执行标准按产品实际适用范围与最新有效版本核实，不直接把模板当作法律或检测结论。
